## 3. "Repository ne demek? Bizde neye denk geliyor?"

Bir araç değil, **senin yazdığın kod katmanı**. Kural: Prisma çağrıları
**sadece** o katmanda olur.

```
UI (React)            → "randevuları göster" der, nasıl geldiğini bilmez
  ↓
API (route handler)   → Zod ile doğrular, yetki bakar, HTTP çevirir
  ↓
Servis (iş mantığı)   → "aynı gün ikinci randevu alınamaz" burada
  ↓
Repository (Prisma)   → SADECE veri erişimi: prisma.randevu.findMany(...)
  ↓
PostgreSQL
```

Projede karşılığı: `src/server/repositories/randevu.repository.ts` gibi bir
dosya. İçinde iş kuralı **yok**. **Prisma** araç, **repository** o aracı
kullanan katman.

**Neden ayrı:** yarın Prisma'dan başkasına geçersen sadece o katman değişir; ve
iş kuralını veritabanına hiç gitmeden test edebilirsin.

## 4. "Contract ne demek?"

Frontend ile backend'in *"bu API ne alır, ne döner"* konusunda anlaşması.
Stack'te `packages/contracts` klasöründe **Zod şeması** olarak duruyor — tek
yerde tanımlı, iki taraf da aynısını kullanıyor.

**Somut faydası:** API'de `basvuruTarihi` alanını `tarih` diye değiştirirsen
frontend **derlenmez**. Hata sen fark etmeden canlıya gidemez. Sözleşme olmasa
hata çalışma anında, kullanıcının ekranında çıkardı.

## 5. "Test uzmanına ihtiyacım var mı? TestSprite kullanmalı mıyım?"

**Hayır — ama bir test uzmanının kafasındaki listeye ihtiyacın var.**

TestSprite senin durumunda **gereksiz**: zaten chrome-devtools MCP, TDD, axe
(erişilebilirlik) ve Lighthouse (performans) var. TestSprite bunların üstüne
bağımsız bir QA katmanı ekler — tek kişilik ekipte o katman zaten sensin.
Ek araç ek bakım demektir.

ChatGPT'nin *"önce kendin manuel test et"* demesi doğruydu ama eksikti:
**neye bakacağını** söylemiyordu.

### Kite yazılan: BEŞ GÖZLE DOĞRULAMA (`06-testing.md`)

Bir özellik bitince sırayla:

| # | Göz | Ajan ne yapar | Sen gözle neye bakarsın |
|---|---|---|---|
| 1 | **Backend** | Mutlu yol, hata yolları, yetkisiz erişim, sınır değerler (0, 1, çok uzun metin, Türkçe karakter), eşzamanlılık | — (ajan kanıt sunar) |
| 2 | **Veri** | Kayıt gerçekten yazıldı mı — `prisma studio` ile bakılır, yetim kayıt var mı | Studio ekranında kendi kaydını gör |
| 3 | **Frontend** | 375/768/1440px · açık+koyu tema · konsol ve ağ hatası · dört ekran durumu | Ekran görüntüleri: metin taşıyor mu, hizalar tutuyor mu |
| 4 | **Tasarım/UX** | Tasarım ADR'sine uygun mu, AI slop var mı, her eylem 100ms içinde karşılık veriyor mu | **Asıl senin katmanın:** *"çalışıyor ama saçma"* dediğin yer |
| 5 | **Güvenlik + işletme** | Yetki ve sahiplik, girdi doğrulama, hata mesajı sızıntısı, N+1 sorgu, performans bütçesi | — (ajan kanıt sunar) |

### Artı iki zorunluluk

**Etki alanı** — her özellikte üç soru yazılı cevaplanır:
1. Hangi **başka ekranları** etkiliyor?
2. Hangi **başka API uçlarını** etkiliyor?
3. Veri modeli değiştiyse hangi **eski kayıtlar** etkilendi?

⛔ *"Sadece şu dosyaya dokundum"* cevap değildir. Etkilenen yerlerden **en az
biri fiilen açılıp kontrol edilir.**

**Öğretme zorunluluğu** — ajan ne kontrol ettiğini **ve neden o kontrolü
yaptığını** anlatır:

> *"Aynı anda iki randevu denedim, çünkü iki kişi aynı saniyede tıklarsa çift
> kayıt oluşabilir — benzersiz index bunu veritabanı seviyesinde engelliyor."*

⛔ *"Test geçti"* tek başına rapor değildir. Neyin test edildiği söylenmezse
neyin test **edilmediği** bilinemez.

Yeni terimler `ogrendiklerim.md` → *"Artık biliyorum"* listesine ekleniyor;
ajan sonraki oturumda o terimi baştan anlatmıyor.

## 6. "Docker'daki PostgreSQL'e bakıp tabloları ve ilişkileri görebilir miyim?"

**Evet, TypeORM'a gerek yok — Prisma'nın karşılığı daha iyi.**

```bash
npx prisma studio     # tarayıcıda localhost:5555
```

Excel tablosu gibi açılır; ilişki alanına tıklayınca bağlı kayda gidersin.
Docker'daki Postgres'e `DATABASE_URL` üzerinden bağlanır, ek kurulum yok.

**ER diyagramı** Prisma'da hazır gelmiyor ama `prisma-erd-generator` ile
`schema.prisma`'dan **otomatik** üretiliyor — şema değişince diyagram da
güncelleniyor.

⛔ **Elle çizilmez.** Elle çizilen diyagram ilk şema değişikliğinde yalan söyler
ve kimse fark etmez.

⛔ **Üretim veritabanına Studio ile bağlanılmaz.** Yanlışlıkla kayıt silmek tek
tıklıktır.

### Senin sorduğun ayrım — doğru soruydu

| Proje | Gerekli mi |
|---|---|
| Backend'i biz yazıyoruz | ✅ Evet — veri modelini görmeden doğru API tasarlanmaz |
| API tasarlıyoruz | ✅ Evet |
| Yalnızca hazır API tüketiliyor | ➖ Hayır — bize lazım olan **API sözleşmesi** |
